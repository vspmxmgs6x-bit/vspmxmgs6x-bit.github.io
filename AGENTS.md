# Portfolio Project Rules

## Never publish

- Phone number, home address, or personal email.
- Grades, salary, visa status, or date of birth.
- Anything in `private/`; add `private/` to `.gitignore` first.
- Credentials, access tokens, account identifiers, signatures, references' contact details, or private metadata.
- Invented employers, dates, titles, achievements, metrics, education, skills, links, endorsements, or personal claims.

## Ask Matthew first

- Before any Git push, GitHub change, deployment, or publication.
- Before deleting or overwriting a file.
- Before materially rewriting, omitting, reordering, or changing the meaning of resume content, except for information covered by the Never publish rules.
- Before adding third-party trackers, analytics, cookies, external fonts, embedded forms, or services that send visitor data off-site.

## Style

- Use plain HTML and CSS with a clean, minimal presentation.
- Present the portfolio as a gallery page that links to each project or detailed work entry.
- Use a professional-and-casual voice.
- Use Columbia blue as the primary accent with white, navy, and accessible neutral colors.
- Keep navigation streamlined, responsive, keyboard-accessible, and easy to scan.
- Preserve the resume's section order and factual content, subject to the Never publish rules.
- Avoid generic filler, inflated language, excessive animation, visual clutter, and placeholder content.

## Change discipline

- Preserve user-authored files and unrelated changes.
- Keep edits scoped to the requested work and verify the site locally before handoff.
- When finished, report every file created or changed, what changed, what was skipped, and any verification limits.
